# Refresh worker lanes and reconnect wakeups

The default `python -m personal_context.refresh_worker --once` remains compatible with existing installations. To prevent slow Mac collection from delaying independent work, run separate serialized service/timer pairs with `--once --lane mac`, `--once --lane obsidian`, and `--once --lane saved_video`. The `local` lane handles all local commands and should not be run at the same time as both per-source lanes. A lane claims at most one job per invocation; shared ledger locking, job leases, per-source locks and existing duplicate-request coalescing remain in effect. Mac collection retains its shared native collection lock.

For a vault reconciled over the Mac, set `sources.obsidian.requires_mac` to `true` in the private refresh configuration. This checks the configured `mac_target` through host-key-verified, non-interactive SSH and leaves the refresh in `waiting_for_device` if the Mac is unavailable. Leave this setting absent for independent direct-cloud backends.

Run `python -m personal_context.refresh_worker --reconnect-check` periodically from a separate service/timer with the same private refresh environment. On startup or an offline-to-online transition it releases backoff for Mac-dependent jobs waiting specifically on device availability; it does not alter running jobs, lock-contention waits, or other failure states. This is an SSH reachability signal, not proof that native applications have fetched data or that a refresh completed. Use the ordinary refresh status and correlated receipt to verify completion. Rate and timeout choices should be appropriate to the installation; each check makes an SSH connection.
