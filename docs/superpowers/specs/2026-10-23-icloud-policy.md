# Native-tag-aware iCloud Drive

User requirements: native Finder/iCloud tags; exclude every identification-tagged file; folder segmentation; tag/folder/name/date/type filters; newer-first default; sentence-based multi-file retrieval through the existing shared OpenAI subscription; tagging, mkdir and moves only for writes, no deletion.

Rclone has no native Finder-tag API. All MCP file operations therefore use a live Mac filesystem receiver with native Finder extended attributes, including ancestor checks. No Rclone data fallback is permitted. Native state is the Mac's synced view, not proof of instantaneous cloud convergence. Unknown tags and inaccessible paths deny access. identification matching is Unicode normalized, trimmed and case insensitive; tagged folders protect descendants. No persistent content index; every search checks current metadata before returning candidates. Smart retrieval sends at most 40 allowed metadata candidates and up to 10 bounded text excerpts to shared subscription inference; returns existing validated paths only.

Named segments map to relative folder roots; the default drive segment is the whole configured root. Filters intersect scope and protection; modification time descending is default. Dates accept ISO dates or timezone-aware timestamps. Writes require exact revision, apply only to allowed items/parents, preserve unrelated tags, and disallow removing identification. Native exclusive rename has no overwrite, cross-device copy or delete fallback. Folder moves are rejected; the requested move capability applies to regular files only. All operations reject symlinks and special files. Writes are never automatically retried after uncertain delivery. No actual iCloud connection or user-file operations during preparation.
